# Grand Theft Shop

Небольшой интернет-магазин одежды. Это тестовое задание: каталог, карточка товара и корзина. Данные не с сервера, а из локального псевдо-API в `src/services/api.js` — ответы приходят с небольшой задержкой, как будто сеть чуть думает.

Визуально это неоновый «grand theft shop»: свой шрифт, фон, заставка при старте и звук кликов. На логику магазина это не влияет, просто так приятнее кликать.

## Как запустить

Нужны Node.js 18+ и npm.

```bash
npm install
npm start
```

Откроется [http://localhost:3000](http://localhost:3000). Если порт занят, Create React App спросит другой.

Ещё две команды:

- `npm run build` — собрать статику в папку `build`
- `npm test` — запустить тесты (их в проекте нет, скрипт оставлен от шаблона)

Отдельно выкладывать билд никуда не нужно.

## Страницы

| Адрес | Что там |
| --- | --- |
| `/` | Каталог |
| `/?category=1` | Каталог одной категории |
| `/product/1?color=2&size=3` | Карточка с уже выбранными цветом и размером |
| `/cart` | Корзина |

Кнопка «Корзина» есть в шапке на всех страницах. В ней видно, сколько штук лежит внутри и на какую сумму. На узком экране снизу появляется вкладка «Корзина» с тем же счётчиком.

## Что требует задание

Это уже работает.

**Каталог.** Карточка с фото, названием, брендом и ценой. Цена — минимальная среди цветов. Клик ведёт на товар. Поиск по названию, галочка «В наличии» (хотя бы один цвет с хотя бы одним размером) и сортировка «сначала дешевле / сначала дороже» собраны в панели по кнопке «Фильтры». На десктопе и планшете кнопка уезжает вправо, панель выезжает справа и закрывается крестиком. На телефоне панель выезжает снизу на всю ширину, над нижней навигацией.

**Карточка.** Описание, цена выбранного цвета, цвет и размеры. Недоступный для этого цвета размер нельзя нажать. Фото листаются свайпом и точками. Если такого товара нет — экран «Товар не найден» и ссылка в каталог. Пока данные едут, показывается скелетон, а не пустая страница.

**Корзина.** Позиция уникальна как связка «товар + цвет + размер». Повторное добавление увеличивает количество. В корзине количество можно менять (минимум 1) и удалять строку. Видны фото, название, цвет, размер, цена за штуку, количество, сумма строки и итог. Корзина пишется в `localStorage` и поднимается после перезагрузки. Битый или чужой JSON из хранилища просто игнорируется.

**Ссылка на цвет и размер.** Выбранные `color` и `size` живут в адресе карточки. Ссылку можно открыть заново — выбор восстановится. Из корзины товар открывается сразу с тем цветом и размером, которые лежат в позиции. Если в ссылке размер, которого у этого цвета нет, он не выбирается.

**Промокод.** В корзине есть поле. Два кода:

- `SALE10` — скидка 10%
- `FIX100` — скидка 100 ₽, но не больше суммы заказа

После применения видны сумма, скидка и итог к оплате. Неизвестный код показывает ошибку. Скидка считается на клиенте и никуда не сохраняется: обновил страницу — промокод нужно ввести снова.

## Чего в ТЗ не было

Задание это разрешает, в требованиях этого нет.

- **Категории.** «Верхняя одежда», «Нижняя одежда», «Спорт», «Аксессуары» приходят из API и фильтруют каталог. На широком экране они в боковой колонке, на странице каталога — ещё и чипсами. Выбранная категория остаётся в адресе (`?category=`).
- **Цвет и размер в каталоге.** В той же панели «Фильтры» можно отметить несколько цветов и размеров. Товар остаётся в списке, если один его вариант подходит под все выбранные условия. Цена на карточке тогда берётся среди подошедших цветов.
- **Превью справа.** На широком экране при наведении на карточку справа открывается крупное фото, описание и цвета. Клик по цвету ведёт на карточку сразу с этим цветом.
- **Полоска корзины.** Под шапкой на широком экране можно раскрыть последние позиции, пролистать их и удалить, не уходя на страницу корзины. Открыта она или нет — запоминается.
- **Сколько класть в корзину.** На карточке можно выбрать количество, а не только одну штуку за клик.
- **Тост.** После добавления всплывает «Добавлено в корзину».
- **Цветные кружки.** Названия цветов из данных («черный», «белый», «хаки» и остальные) рисуются своими оттенками. Структура товаров в `api.js` при этом не менялась.
- **Заставка.** При открытии сайта на пару секунд показывается экран загрузки шрифта. Если в системе включено «уменьшить движение», она короче.
- **Звук.** Клики и наведения звучат. Кнопка с динамиком в шапке выключает звук, выбор сохраняется.
- **Пустые состояния.** Пустой поиск и пустая корзина — отдельные экраны, не просто строчка текста.
- **Телефон.** Каталог, карточка и корзина перестраиваются. Снизу остаётся переключатель «Магазин / Корзина».

## Из чего собрано

React 18, React Router 6, Mantine (кнопки, поля, сетка, тема) и Swiper для галереи фото. Код разложен по Feature-Sliced Design: `app`, `pages`, `widgets`, `features`, `entities`, `shared`. Общие функции лежат в `shared/lib` и импортируются оттуда. Псевдо-API по условию задания остаётся в `src/services/api.js`, в приложение его отдаёт `shared/api`. Корзина — сущность на React context и `useReducer`. Страницы подгружаются отдельно, поэтому первый экран не тянет сразу весь магазин.

# Задача

Реализовать мини‑каталог товаров на React.

Данные о товарах нужно получать из псевдо‑API, которое находится тут - `src/services/api.js`

Нужно сделать 3 страницы:
1. Список товаров;
2. Детальная страница товара;
3. Корзина;

Выбор библиотек для реализации страниц не ограничен.

Вёрстка и стилизация не является ключевым фактором - важнее корректность, структурность, чистота реализации.

---

## Требования

### 1) Список товаров (начальная страница)
- Показать товары с картинкой, названием и ценой (остальное по желанию).
- По клику на товар - переход на карточку товара.
- Реализовать поиск, фильтры, сортировку:
  * поиск по названию (строка)
  * фильтр "в наличии" - у товара есть хотя бы один цвет с хотя бы одним доступным размером.
  * сортировка по цене `asc`/`decs` - цену товара брать как минимальную из его цветов.

### 2) Карточка товара (детальная страница)
- Вывести информацию о товаре.
- Просмотр изображений через переключение без использования сторонних библиотек.
- Реализовать выбор цвета.
- Реализовать выбор размера:
  * показывать список всех размеров как отдельные кнопки.
  * недоступные размеры для выбранного цвета должны быть заблокированными.
- Добавление в корзину можно сделать по кнопке в количестве одной штуки за раз.
- Если товара нет - показать экран "Товар не найден" + ссылка назад.

### 3) Корзина
- Кнопка перехода в корзину должна быть на каждой странице.
- Вывод суммы количества добавленных товаров и их стоимости в кнопку перехода на страницу корзины.
- Корзина хранит уникальные позиции в связке `продукт + цвет + размер`.
- Корзина должна сохраняться в `localStorage` и восстанавливаться при перезагрузке страницы.
- Для каждой позиции поддерживается количество:
  * при добавлении уже существующей позиции увеличиваем количество на 1.
  * в корзине можно менять количество (минимум 1) и удалять позицию.
- На странице показывать:
  * список добавленных позиций: изображение, название товара, выбранный цвет, выбранный размер, цена, количество, сумму стоимости позиции.
  * общую сумму всех позиций.

### 4) UX
- Не должно быть runtime‑ошибок в обычных сценариях и особенно при старте проекта. Проверяйте, пожалуйста, перед отправкой своей работы.
- При переходах/действиях пользователь должен видеть адекватные состояния (загрузка/ошибка/пусто и т.п.).

### 5) Состояние в URL
- Сохранять выбранный `color` и `size` на детальной странице в url и восстанавливать состояние при открытии ссылки.

### 6) Промокод
- Поле применения промокода - в корзине пересчитывается стоимость товаров с отображением скидки.
- Формат промокода и формат скидки (процентная/фиксированная) - произвольные.
